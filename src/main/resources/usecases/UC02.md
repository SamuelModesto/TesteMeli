# **Caso de Uso UC01 – Consultar Detalhes do Produto**

## **Descrição**
Implementacao de tratamentos de excecoes para consultar detalhes de um produto.

## **Ator Principal**
- Cliente.

## **Pré-condições**
- Ao receber os dados incorretos ou cenarios de excecao deve devolver o status code correto e uma mensagem de erro.

  | Status Code | Nome | Quando utilizar | Mensagem padrão | Observações |
  |------------|------|----------------|------------------|-------------|
  | **200** | OK | Consulta realizada com sucesso (GET) | — | Retorna o recurso solicitado no corpo da resposta |
  | **400** | Bad Request | Erros de validação (Jakarta Validation) ou JSON inválido | "Requisição inválida. Verifique os campos enviados." | Recomenda-se listar os erros específicos (ex.: "O campo 'nome' é obrigatório.") |
  | **404** | Not Found | Recurso não encontrado no banco de dados | "O recurso solicitado não foi encontrado." | Usado quando o identificador informado não corresponde a nenhum registro |
  | **422** | Unprocessable Entity | Erros semânticos ou regras de negócio que impedem o processamento | "Não foi possível processar as instruções contidas na requisição." | Difere do 400 pois a sintaxe é válida, mas a regra de negócio falhou |
  | **500** | Internal Server Error | Erros inesperados ou exceções não tratadas | "Ocorreu um erro interno no servidor. Tente novamente mais tarde." | Deve ser logado para análise técnica |
  | **503** | Service Unavailable | Serviço temporariamente indisponível (ex.: banco fora do ar) | "Serviço temporariamente indisponível." | Indica falha transitória; pode ser usado com retry |

- A excecao deve ser lancada e capturada pelo controllerAdvicer.
- O controllerAdvicer deve retornar o status code correto e a mensagem de erro.

## **Pós-condições**
- Obter resposta com status code correto com uma mensagem de erro generica sem informacoes de campos.
- Obter uma mensagem de erro via log ou aviso coerente com o contexto.
---

## **Fluxos de Sucesso**
**Consulta realizada com sucesso (GET)**

## **Fluxos de Excecao**
**1.E – Recurso não encontrado no banco de dados**

**2.E – Erros de validação (Jakarta Validation) ou JSON inválido**

**3.E – Erros semânticos ou regras de negócio que impedem o processamento**

**4.E – Erros inesperados ou exceções não tratadas**

**5.E – Serviço temporariamente indisponível (ex.: banco fora do ar)**

OBS: Para saber qual status usar, consulte a tabela de pré-condicoes.
